# Localization (English / Arabic)

The whole frontend ships in **English (default)** and **Arabic (RTL)**. Routes are **not** locale-prefixed: every existing URL
(`/`, `/products`, `/account/...`, `/dashboard`, `/orders`, ...) keeps working and the language is a per-browser preference.

## Namespaces

`common`, `auth`, `customerAuth`, `customer` (customer portal), `site` (public website; named `site` because `public` is a reserved word), `tracking`, `samples`, `orders`, `production`, `quotations`, `payments`, `fulfillment`, `customers`, `brands`, `management`, `masterData`, `responsibilities`, `dashboard`, `notifications`, plus `codes` (statuses/enums), `roles` and `phrases` (text that lives in constants).

## How it works

| Piece | Where |
|---|---|
| Locale list, cookie name, `lang`/`dir`, Intl locales | `src/i18n/config.ts` |
| Dictionaries (type-checked, one file per area) | `src/i18n/messages/{en,ar}/<namespace>.ts` |
| Translator (`t`, `t.text`, `t.plural`, `t.dyn`) | `src/i18n/translate.ts` |
| Dates / numbers / money / durations / status & role names | `src/i18n/format.ts` |
| Client provider + `useI18n()` | `src/i18n/provider.tsx` |
| Server access (`getI18n()`, `localizedTitle()`) | `src/i18n/server.ts` |
| EN / العربية switcher | `src/i18n/language-switcher.tsx` |
| "Active locale" for code outside React (module-level tables) | `src/i18n/active.ts` |

* **Persistence:** a plain, non-sensitive cookie `bp_locale` (`en` | `ar`, 1 year, `SameSite=Lax`). It is the only thing the switcher writes.
  Auth cookies (`bp_rt`, `bp_c_rt`, `bp_session`, `bp_c_session`) and the in-memory access tokens are never touched.
* **Default:** English. The browser's language is deliberately **not** used.
* **Switching:** writes the cookie, updates `<html lang dir>` immediately and calls `router.refresh()`: the current route re-renders in
  place (no navigation, no logout, client state and the auth providers are preserved).
* **Server rendering:** `app/layout.tsx` reads the cookie, so the first paint already has the right `lang`/`dir`. Reading cookies makes
  the application routes *dynamic* (server-rendered per request); `sitemap.xml` and `robots.txt` stay static.
* **Type safety:** `ar` is typed against `en`; a missing Arabic key is a compile error and `t("ns.key")` only accepts existing keys.

## Writing UI text

```tsx
const { t, fmt } = useI18n();          // client components
<Button>{t("common.save")}</Button>
t("samples.samplenumberV2Done", { sampleNumber, v2 })     // {placeholders}
t.plural("dashboard", "count_order", n)                    // CLDR plurals: ...One/Two/Few/Many/Other
fmt.date(x) / fmt.dateTime(x) / fmt.number(n) / fmt.money(amount, "EGP") / fmt.duration(min)
fmt.code("IN_PRODUCTION")                                  // "In production" / "قيد الإنتاج"
fmt.role("SUPER_ADMIN")                                    // "Super Admin" / "المدير العام"
```

Server components: `const { t } = await getI18n()`.

Text that lives in constants (catalogue copy, legal text, label maps, table columns) keeps its English source and is looked up by that
exact string in `messages/*/phrases.ts` (`t.text("English")`, `loc(CONSTANT)`, `localizedMap({...})`, `tx("English")` outside React).
A missing phrase falls back to the English text, never an empty string.

## Statuses, enums, roles and permissions

Backend values are the contract and are **never** translated or sent translated. `messages/*/codes.ts` maps a code to a *display* text
(one canonical translation per status); `roles.ts` does the same for role codes. Permission identifiers (`samples.read`, ...) are not
shown translated. A test asserts that no source file builds an API field (`action`, `status`, `mode`, `reason`, ...) from `t(...)`.

## RTL rules

* `<html dir="rtl">` plus Radix's `Direction.Provider` (menus, selects, tabs, popovers) and Sonner's `dir`.
* The code base already used logical utilities (`ms-/me-/ps-/pe-/start-/end-`, `border-e`); remaining directional pieces use `rtl:`
  variants (arrows `rtl:-scale-x-100`, chevrons, hover nudges). Only navigation arrows mirror; logos, garment art, video, checkmarks,
  download/upload icons do not.
* Inputs that hold technical values (email, tel, url, password, numbers, codes, tokens) are forced `dir="ltr"` (`components/ui/input.tsx`).
* Carousels (`SnapRow`, garment carousel, mobile process) centre items from on-screen rectangles (`lib/utils/scroll.ts`), so snap, dots
  and Back/Next stay correct in RTL.
* Typography: IBM Plex Sans Arabic (self-hosted via `@fontsource`, loaded only when Arabic glyphs are needed) sits behind Geist in the
  font stacks, so English is unchanged. `html[lang="ar"]` rules in `globals.css` remove uppercase, letter-spacing and the very tight
  display line-heights, which break Arabic joins and clip marks.

## SEO

Titles, descriptions, Open Graph/Twitter text and JSON-LD follow the cookie. The canonical URL, robots and sitemap are unchanged.
Because there are no locale-prefixed URLs, **no `hreflang` alternates are emitted** (they would have to point at URLs that do not
exist), and crawlers (which send no cookie) always see English. Adding real per-language URLs is a separate, larger change.
The generated Open Graph *image* stays English (the image renderer has no Arabic font loaded).

## Known intentional exceptions

* Decorative drafting callouts inside the garment illustrations (`FRONT`, `SLEEVE`, `CHEST`, ...) are aria-hidden art and stay Latin.
* Text written by the backend (validation sentences, activity titles, product/fabric names, notes, courier names) is shown as received.
  Frontend-authored fallbacks and the known customer `nextStep` copy are translated.
* BFF JSON error bodies (`/api/auth/*`) are machine responses, not UI.
* The Arabic legal text (Privacy / Terms) is a faithful translation of a draft that is itself marked "to be confirmed": have it reviewed
  by a native speaker and by the company's lawyer before relying on it.
